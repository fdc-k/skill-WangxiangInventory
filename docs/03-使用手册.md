# 03 · 使用手册

## 先记住这一张「写法对照表」

这个文档里的命令，Mac 和 Windows **只差一个地方**：

| | Mac / Linux | Windows |
|---|---|---|
| Python 在哪 | `.venv/bin/python` | `.venv\Scripts\python` |
| 路径斜杠 | `/` | `\` |
| 例子 | `.venv/bin/python -m wangxiang diff` | `.venv\Scripts\python -m wangxiang diff` |

**不想打命令？** 直接双击 `bin` 文件夹里同名的文件就行：

| 命令 | 双击这个（Windows） | 双击这个（Mac） |
|---|---|---|
| `check` | `bin\setup.bat` | `bin/setup.command` |
| `extract` | `bin\1-提取库存.bat` | `bin/1-提取库存.command` |
| `diff` | `bin\2-差异比对.bat` | `bin/2-差异比对.command` |
| `sync` | `bin\3-同步更新.bat` | `bin/3-同步更新.command` |
| `selftest` | `bin\4-离线自检.bat` | `bin/4-离线自检.command` |

下面的命令都假设你**先进入项目文件夹**（终端里 `cd` 过去）。
统一写法：`.venv/bin/python -m wangxiang <命令> [选项]`
（**Windows 请把 `.venv/bin/python` 换成 `.venv\Scripts\python`**）

---

## 命令总览

| 命令 | 作用 | 会不会改线上数据 |
|---|---|---|
| `check` | 环境、来源文件、网店连接自检（联网） | ❌ 不会 |
| `selftest` | 离线回归自检：解析结果是否还和基线一致 | ❌ 不会 |
| `extract` | 读取来源文件 → 统一格式 Excel | ❌ 不会 |
| `diff` | 和线上库存比对 → 彩色差异报表 | ❌ 不会 |
| `sync` | 按差异更新网店（**默认演练**） | ❌ 不会 |
| `sync --yes` | 真正更新网店 | ✅ **会** |
| `map` | 查看商品匹配建议 | ❌ 不会 |
| `map --write` | 把匹配建议写入 `config/product_map.csv` | ❌ 不会 |

公共选项：`--config 路径`（默认 `config/config.yaml`）、`--version`。

## 1. `check` —— 自检

```bash
.venv/bin/python -m wangxiang check
```

检查三件事：Python 依赖是否齐全、来源文件是否存在、WooCommerce 密钥能不能连上。

```
[1/3] 检查依赖
  ok  openpyxl
  ok  pdfplumber
  ok  requests
  ok  yaml
[2/3] 检查来源文件
  ok  [SP5] /…/demo-inventory/10.5SP5蜘蛛库存表.xlsx
[3/3] 测试 WooCommerce 连接
  ok  连接成功，店铺返回了 1 条商品样本
```

任何一步失败，按提示处理（详见 [07-常见问题FAQ](07-常见问题FAQ.md)）。

## 1b. `selftest` —— 离线回归自检

```bash
.venv/bin/python -m wangxiang selftest
```

**完全不访问网络**，约 30 秒，检查四件事：

```
[1/4] 解析来源文件并与基线对比
  ok  [SP5]   84 行 /  18 商品
  ok  [ALO]   73 行 /  15 商品
  ok  [PALLET]  850 行 / 130 商品
[2/4] 检查货盘 PDF 的打勾识别质量
  ok  [PALLET] 打勾格 850 个：552 个有勾 / 298 个无勾 / 0 个临界
[3/4] 检查商品映射表
  ok  映射表 163 行，已填 parent_sku 89 行
[4/4] 检查规范化逻辑（SKU / 尺码 / 数量 / 重名编号）
  ok  ...
✅ 自检全部通过。
```

**什么时候跑**：改了来源文件、改了 `wangxiang/` 里的解析代码、换电脑部署之后。
数量对不上就说明解析结果变了，需要人工确认是「来源真的变了」还是「代码改坏了」。
基线数字写在 `tests/baseline.json`，确认无误后可以直接改那个文件。

## 2. `extract` —— 提取与拆分

```bash
.venv/bin/python -m wangxiang extract
# 只处理其中一个来源（不会覆盖「全部库存_合并.xlsx」）：
.venv/bin/python -m wangxiang extract --sources SP5,ALO
```

**输出**：`output/unified/`

| 文件 | 内容 |
|---|---|
| `SP5_统一库存.xlsx` | 该来源的统一格式库存 |
| `ALO_统一库存.xlsx` | 同上 |
| `PALLET_统一库存.xlsx` | 同上 |
| `全部库存_合并.xlsx` | 所有来源拼在一起 |
| `extract_stats.json` | 每个来源处理了多少行、多少商品、有没有异常 |

统一格式的 7 列：

| 列名 | 含义 |
|---|---|
| `source` | 来源标识（`SP5` / `ALO` / `PALLET`） |
| `category` | 分区/品类（如 `卫衣(hoodie)`、`Sp5der｜裤子(pant)`） |
| `source_product` | 来源里的商品名或货号 |
| `size` | 尺码（已统一成 XXS/XS/S/M/L/XL/XXL 写法） |
| `quantity` | 数量；**空白 = 来源没有告诉数量** |
| `availability` | `instock`（有货）/ `outofstock`（缺货） |
| `source_ref` | 这条数据出自原文件的哪里（方便回溯核对） |

## 3. `diff` —— 差异比对（核心）

```bash
.venv/bin/python -m wangxiang diff
.venv/bin/python -m wangxiang diff --refresh      # 强制重新拉取网店数据
.venv/bin/python -m wangxiang diff --limit 50     # 终端预览多显示一些
.venv/bin/python -m wangxiang diff --json out.json
.venv/bin/python -m wangxiang diff --combo        # 允许用「组合商品」货号匹配
```

**流程**：
1. 重新读取 `output/unified/` 里的统一格式文件（这就是需求里的「再次读取」）；
2. 从 WooCommerce 拉取全部商品与变体（缓存到 `output/.cache/woo_catalog.json`）；
3. 逐条把「来源商品 + 尺码」对上「网店商品 + 变体」；
4. 比较数量与有货/缺货状态；
5. 输出报表。

**输出**：

| 文件 | 说明 |
|---|---|
| `库存差异_<时间戳>.html` | **双击用浏览器打开**，带颜色，中文和颜色在任何系统都不会跑掉（推荐给非技术同事） |
| `库存差异_<时间戳>.xlsx` | Excel 版，带颜色，方便筛选排序 |
| `库存差异_<时间戳>.md` | 纯文本版，方便贴到聊天工具 |

Excel 版的四个工作表：

| 工作表 | 内容 | 颜色规则 |
|---|---|---|
| **差异明细** | 和网店不一致的条目 | 整行浅红；真正变化的「来源数量/在线数量/数量差/状态」单元格**深红加粗** |
| **无差异** | 和网店完全一致的条目 | 浅绿 |
| **需人工处理** | 网店没有这个商品 / 没有这个尺码 / 没匹配上 | 浅黄 |
| **待处理商品清单** | 上表按商品去重汇总（一商品一行，含尺码列表和处理建议） | 浅黄 |
| **汇总** | 统计数字 | |

同时输出 `库存差异_<时间戳>.md`（纯文本版，方便发微信/贴群）。

**「待处理商品清单」页会给出「近似货号建议」**：如果你的货号和店里的只差一两位，
工具会把它猜出来放在那一列（并标注是不是「组合款」），你确认后填进
`config/product_map.csv` 的 `parent_sku` 再重跑 diff 即可。

**状态有几种**：

| 状态 | 含义 | 会不会被 sync 更新 |
|---|---|---|
| 有差异 | 数量或状态和网店不一样 | ✅ 会 |
| 一致 | 完全一样 | ❌ 不需要 |
| 本店无此商品 | 这张表里找不到对应商品 | ❌ 需要人工处理 |
| 本店无此尺码 | 商品找到了，但没有这个尺码的变体 | ❌ 需要人工处理 |
| 未能匹配 | 没有人工映射、自动匹配也没成功 | ❌ 需要人工处理 |
| 需人工填数量 | 来源只说「有货」，但网店该变体管理库存且数量为 0，工具不猜数字 | ❌ 需要人工处理 |

## 4. `sync` —— 同步更新

```bash
.venv/bin/python -m wangxiang sync                       # 演练：打印将要发送的内容，不提交
.venv/bin/python -m wangxiang sync --yes                 # 真正提交
.venv/bin/python -m wangxiang sync --yes --refresh       # 顺便重新拉取线上数据

# 只同步一部分（第一次上手强烈建议这样试）
.venv/bin/python -m wangxiang sync --yes --only-source SP5
.venv/bin/python -m wangxiang sync --yes --only-sku 192HO24
```

| 筛选参数 | 作用 | 例子 |
|---|---|---|
| `--only-source SP5` | 只同步指定来源 | `--only-source SP5`、可重复写多次 |
| `--only-sku 关键词` | 只同步「货号 / 商品名 / 来源商品」里含这个关键词的 | `--only-sku 192HO24` |

演练输出：

```
待更新 92 条。
当前为演练模式（不会改动线上数据）。确认要真正更新时请加 --yes。
===== 同步汇总 =====
  计划 92 条，成功 0，失败 0，跳过/演练 92
  明细日志：output/sync/同步结果_20261007-010314.xlsx
```

真实更新后：

```
  [1/92] 成功 192SU-22-4410 / M -> {"stock_quantity": 45, "stock_status": "instock"}
  [2/92] 成功 …
```

**输出**：`output/sync/同步结果_<时间戳>.xlsx`

| 列 | 说明 |
|---|---|
| 结果 | 成功（绿）/ 失败（红）/ 演练 |
| 来源商品、尺码 | 数据来源 |
| 本店 SKU、本店商品、变体 ID | 被更新的对象 |
| 更新前 | 更新前的数量 / 状态 / 是否管理库存 |
| 更新请求 | 实际发给 WooCommerce 的 JSON |
| 更新后 | 提交成功后重新读取到的值 |
| 错误信息 | 失败原因（HTTP 状态码 + 原始返回） |

**更新规则**（由 `config/config.yaml` 的 `sync.mode` 决定）：

| mode | 行为 |
|---|---|
| `auto`（默认） | 网店该变体「管理库存」→ 同步数量；否则只同步有货/缺货 |
| `quantity` | 一律按数量同步（会给变体打开「管理库存」） |
| `status` | 一律只同步有货/缺货，不动数量 |

补充规则：
- 来源**没有数量**（如货盘 PDF 的 ✅）但变体**管理库存**时，按
  `sync.no_qty_policy` 处理：

  | 取值 | 行为 |
  |---|---|
  | `status_and_zero`（默认） | 判**缺货**时把数量一起置 0（避免出现「缺货但还挂着 5 件」）；判**有货**时只改状态，数量不动 |
  | `status` | 数量原样不动，只改有货/缺货 |

- 如果来源说「有货」，但网店该变体管理库存、数量却是 0，工具**不会凭空猜一个数字**，
  会把这行放进「需人工处理」，状态记为 **需人工填数量**。请人工在网店填上实际数量。
- `sync.update_status` 设为 `false` 时，连状态也不动，只动数量。

## 5. `map` —— 商品映射

```bash
.venv/bin/python -m wangxiang map             # 只查看建议
.venv/bin/python -m wangxiang map --write     # 写入 config/product_map.csv
.venv/bin/python -m wangxiang map --overwrite --write   # 丢弃旧映射重新生成
```

**匹配优先级**（从高到低）：

1. `config/product_map.csv` 里你手工写的 `parent_sku`；
2. 来源里的货号与网店商品货号**完全相同**（忽略 `-`、空格、大小写，
   并且自动兼容网店货号结尾多一个 `F` 的情况）；
3. 商品名完全相同；
4. 商品名相似度 ≥ `options.fuzzy_threshold`（默认 0.86）；
5. 都失败 → 归入「未能匹配」。

细节见 [06-商品映射表说明](06-商品映射表说明.md)。

## 5b. `rollback` —— 一键撤回

每次执行同步（包括演练）都会在 `output/sync/` 生成一份**回滚快照**，
里面记着每条变体「改之前」的数量和状态。

```bash
# 先演练，看会还原成什么
.venv/bin/python -m wangxiang rollback output/sync/回滚快照_20261007-012230.json

# 真还原
.venv/bin/python -m wangxiang rollback output/sync/回滚快照_20261007-012230.json --yes
```

还原结果写到 `output/sync/回滚结果_<时间>.xlsx`。

> 快照只包含「那次同步碰过的变体」。演练模式的快照里记的是当时的线上值，
> 虽然不会提交任何改动，但可以直接拿来验证「如果现在回滚会变成什么」。

## 6. 装好之后也可以用 `wangxiang` 短命令

`bash bin/setup.sh` 会把本工具安装进自己的独立环境，之后在任何目录都能这样跑：

```bash
.venv/bin/wangxiang diff
.venv/bin/wangxiang sync --yes
```

等价于 `python3 -m wangxiang ...`，只是少打几个字。
