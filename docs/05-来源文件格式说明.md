# 05 · 来源文件格式说明

工具通过 `adapter`（解析器）理解来源文件。目前有两种。

`config/config.yaml` 里每个来源是这样一段：

```yaml
sources:
  - id: SP5                     # 唯一标识，会写进报表的「来源」列
    label: "SP5 蜘蛛库存表"        # 显示用名字
    file: "demo-inventory/10.5SP5蜘蛛库存表.xlsx"   # 文件路径（相对本文件夹）
    adapter: excel_table         # 用哪个解析器
    options:                     # 解析器的参数
      sheet: Sheet1
      product_column: H
      size_column: I
      quantity_column: J
```

加一个新文件 = 在 `sources:` 下面再加一段，**不需要改代码**。

---

## adapter: `excel_table`（普通 Excel 表格）

### 适用

一张表里，纵向排列着「商品名 / 尺码 / 数量」三列。商品名或尺码可以跨行合并
（合并单元格只在左上角存值，本工具会自动向下填充）。

典型例子：

|  | B | C | D |
|---|---|---|---|
| 1 | ALO 3031黑色圆领 | XS | 92 |
| 2 | (合并) | S | 135 |
| 3 | (合并) | M | 56 |
| 4 | | | |
| 5 | ALO 3031灰色圆领 | XS | 20 |

### options

| 参数 | 必填 | 说明 |
|---|---|---|
| `sheet` | 否 | 工作表名；不写就用第一个工作表 |
| `product_column` | 是 | 商品名所在列，写字母（`A`~`ZZ`） |
| `size_column` | 是 | 尺码所在列 |
| `quantity_column` | 否 | 数量所在列；**不写 = 该来源只提供有货/缺货** |
| `start_row` | 否 | 从第几行开始读（默认 1，用于跳过表头） |
| `stop_row` | 否 | 读到第几行结束（默认到最后一行） |
| `in_stock_values` | 否 | 数量列里表示「有货」的文字，如 `["✅", "Y"]` |

### 判断规则

- 有 `quantity_column`：数字 > 0 → 有货；= 0 → 缺货。
  如果格子里是文字，且在 `in_stock_values` 里 → 有货。
- 没有 `quantity_column`：一律记为「有货」（因为没有别的信息）。

### 怎么知道列号？

打开 Excel，最上面一行的 **A B C D …** 就是列名。
如果 A 列是空的而数据从 B 列开始，就写 `product_column: B`。

> 提示：把 Excel 的第一行冻结、横向拉宽，很容易数清楚列。

## adapter: `pdf_pallet`（货盘 PDF）

### 适用

一种「货盘清单」PDF，特征：

- 一整页超长表格，用**灰色标题条**分成若干品牌/品类分区，
  例如 `卫衣（hoodie）` / `裤子（pant）` / `平脚裤（relaxed）` / `短裤（short）` /
  `zip up 拉链` / `ALO` / `Stussy` / `Sp5der` / `Kith T-shirt`；
- 每个商品是一块：左边商品图 + 中英文名 + 货号，右边一列尺码；
- 尺码右边一格有 **✅ 或 ☑** 表示**有货**，空白表示**缺货**；
- 尺码自上而下递增（XXS → XXL）。

### options

| 参数 | 必填 | 说明 |
|---|---|---|
| `page` | 否 | 第几页（默认 1） |
| `default_section` | 否 | 没有分区标题时的默认分区名 |
| `section_columns` | 否 | 分区名 → 左右两栏分别代表什么，用来把货盘里的名字对上网店商品 |
| `drop_unidentified` | 否 | 连名字都提不出来的块是否丢掉（默认 `true`） |

`section_columns` 示例：

```yaml
section_columns:
  Sp5der:       ["卫衣(hoodie)", "裤子(pant)"]
  ALO:          ["上衣(tops)",   "裤子(pants)"]
  Stussy:       ["上衣(tops)",   "上衣(tops)"]
  Kith T-shirt: ["T恤(tee)",     "T恤(tee)"]
```

这样货盘里两个都叫 `Brown` 的商品（Sp5der 上有两个颜色都叫 Brown 的裤子）
会被区分为 `Sp5der｜裤子(pant)` 分区里的第 1 个和第 2 个，
在 `product_map.csv` 里分别用 `Brown#1`、`Brown#2` 指定，见
[06-商品映射表说明](06-商品映射表说明.md)。

### 解析器怎么工作（方便排查）

1. 扫描所有灰色标题条，把整页切成若干分区；
2. 每个分区里按 x 坐标聚类出 1~2 个「尺码列」；
3. 尺码序号一旦不再递增，就认为换下一个商品（所以 5 码 / 6 码 / 7 码混排也能自适应）；
4. 找出所有 ✅ / ☑ 的坐标，按 y 坐标归到对应尺码行；
5. 按 y 坐标把商品块对应到最近的货号；没有货号就用左侧的中英文名当标识。

每一条输出都带 `source_ref`，形如：

```
10.5Essentials 货盘.pdf|Sp5der|栏1|块3|L
```

方便你在 PDF 里定位核对。

## 我要处理一个「完全不同的格式」怎么办

两种做法：

1. **换个思路**：把新格式手工整理成 `excel_table` 认识的三列
   （商品名 / 尺码 / 数量），这是最省事的办法；
2. **写新 adapter**：在 `wangxiang/` 下新增一个模块，实现
   `extract_xxx(path, source_id, options) -> (rows, stats)`，
   然后在 `wangxiang/unify.py` 的 `extract_one_source()` 里注册。
   已经实现的两个（`extract_excel.py`、`extract_pdf.py`）可以当模板。

## 尺码和货号的自动规范化

工具会自动做这些「擦屁股」的事，所以你不用手动改源文件：

- 尺码：去掉「码/号」，`2XL → XXL`；全角转半角；统一大写。
- 货号：忽略 `-`、空格、大小写；
  `192SU-22-4410` 和网店的 `192SU224410F` 会被认为是同一个商品
  （自动兼容网店货号结尾多一个 `F`）。
- 货盘 PDF 里偶尔缺失的尺码文字（例如 `L` 和 `XXL` 之间少了 `XL` 那一行），
  会自动补出并保留对应格子。
