# 06 · 商品映射表 `config/product_map.csv`

> 💡 **Windows 用户**：下面命令里的 `.venv/bin/python` 要换成 `.venv\Scripts\python`。


## 它是干什么的

来源文件里的商品名，和网店里的商品名经常对不上：

| 来源里叫 | 网店里叫 |
|---|---|
| `蜘蛛09款咖啡色(Brown BBV2)上衣 蓝花` | `Sp5der Beluga Hoodie/Brown`（货号 `SP5-H-BROWN-BBV2`） |
| `192SU-22-4410` | `Hoodie Strech Limo/Black`（货号 `192SU224410F`） |
| `ALO 3032黑色帽衫` | （网店还没有这个商品） |

第一种情况工具能自动靠**货号**对上；第二种就要靠**这张映射表**告诉它
「来源里的这个商品 = 网店的这个货号」。

---

## 表格长什么样

用 Excel 或 Numbers 打开 `config/product_map.csv`，是这样：

| source | category | source_product | parent_sku | size_map | note |
|---|---|---|---|---|---|
| PALLET | Sp5der｜卫衣(hoodie) | Brown | SP5-H-BROWN-BBV2 | | 祥旺人工确认 |
| PALLET | Sp5der｜裤子(pant) | Brown#1 | SP5-P-BROWN | | |
| PALLET | Sp5der｜裤子(pant) | Brown#2 | SP5-P-BROWN-BBV2 | | |
| SP5 | | 蜘蛛上青色(NAVY)上衣 | SP5-H-NAVY | | |
| ALO | | ALO 3031黑色圆领 | | | ⚠ 需要人工填写 parent_sku |

### 每一列的意思

| 列 | 说明 | 能不能用 `*` |
|---|---|---|
| `source` | 来源 `id`（就是 `config.yaml` 里 `sources` 的 `id`，如 `SP5` / `ALO` / `PALLET`） | ✅ 写 `*` 表示「所有来源」 |
| `category` | 分区/品类。就是统一格式 Excel 里 `category` 那一列的值 | ✅ 写 `*` 或留空 |
| `source_product` | 来源里的商品名/货号。就是统一格式 Excel 里 `source_product` 那一列的值 | ❌ 必须精确 |
| `parent_sku` | **你要填的**：网店商品的货号（WooCommerce 商品编辑页里的「SKU」） | |
| `size_map` | 尺寸改名，如 `XXL:2XL;L:XL`（网店尺码和来源写法不同才需要） | |
| `note` | 备注，随便写，仅供参考 | |

> `source_product` 必须和统一格式 Excel 里**一模一样**（包括大小写和空格）。
> 最省事的做法：直接从 `output/unified/xxx_统一库存.xlsx` 里复制粘贴。

## 名字重了怎么办：`#1` `#2`

同一个 `source` + `category` 下，如果有两个商品**名字完全相同**，
工具会按出现顺序加上 `#1`、`#2`：

```
Sp5der｜裤子(pant) | Brown#1   →  Sp5der Web Sweatpants/Brown    (SP5-P-BROWN)
Sp5der｜裤子(pant) | Brown#2   →  Sp5der Beluga Sweatpants/Brown (SP5-P-BROWN-BBV2)
```

顺序就是它们在来源文件里自上而下的顺序。改源文件顺序后，
这两个编号的含义可能会换，改完源文件请重新跑 `map` 核对一遍。

## 怎么生成 / 更新这张表

```bash
# 1) 先查看工具的建议（不会改文件）
.venv/bin/python -m wangxiang map

# 2) 满意了再写进文件
.venv/bin/python -m wangxiang map --write

# 3) 想推倒重来（会丢掉你之前手工填的！）
.venv/bin/python -m wangxiang map --overwrite --write
```

`note` 列会写清楚这一行是怎么来的：

| note | 含义 |
|---|---|
| `SKU 相同` | 货号直接对上，**不用管** |
| `名称相似度 0.92` | 靠名字猜的，**建议人工确认** |
| `组合商品 SKU 命中` | 命中的是「组合款」商品（`--combo` 模式才有），**建议人工确认** |
| `⚠ 需要人工填写 parent_sku` | 没匹配上，需要你填 |

## 怎么查网店商品的货号（SKU）

**方法一：后台看**

```
WordPress 后台 → 商品 → 全部商品 → 点开某个商品 → 商品数据 → 库存 → SKU
```

**方法二：问工具**

```bash
.venv/bin/python -m wangxiang map
```

输出里已经给出了建议的 `parent_sku`。

**方法三：用浏览器看接口**

```
https://你的域名/wp-json/wc/v3/products?search=关键词&consumer_key=ck_xxx&consumer_secret=cs_xxx
```

## 常见问题

**Q：填错了 parent_sku 会怎样？**
不会乱改。`diff` 会把它标成「本店无此商品」，并在备注里说明
「product_map.csv 里指定的 parent_sku 在店里不存在」。只有真正匹配上的才会进
`sync`。

**Q：网店尺码写的是 `2XL`，来源写的是 `XXL`，怎么办？**
不用管。工具会自动把 `2XL` 规范化成 `XXL` 再比较（`size_map` 也不用填）。

**Q：那 `size_map` 什么时候用？**
当两边尺码**写法完全不同**、规范化也对不上时。例如网店尺码写的是
`Extra Large`，来源写的是 `XL`：

```
source_product           parent_sku        size_map
Hoodie Strech Limo      192SU224410F      XL:Extra Large
```

**箭头右边的写法请照抄网店里的写法**，工具会原样拿去匹配；
箭头左边是来源文件的写法。多个用 `;` 分隔，例如 `XXL:2XL;L:Large`。

**Q：我只想让一部分商品更新，可以吗？**
可以，把其他行的 `parent_sku` 清空即可——清空后它们会进「未能匹配」，
不会被更新。

**Q：网店里根本没有这个商品怎么办？**
先在 WooCommerce 里把商品建好（含各尺码变体），再回来填 `parent_sku`。
工具目前**不会替你新建商品**，只会更新已有的库存。
