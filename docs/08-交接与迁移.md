# 08 · 交接与迁移（把工具给别人用）

这个 Skill 是**完全自包含**的：整个文件夹复制走就能用，不需要联网下载代码，
不需要数据库，不需要改任何路径。


> 💡 **Windows 用户**：本文里的 `.venv/bin/python` 表示「项目自带环境里的 Python」。
> Windows 上的写法是 `.venv\Scripts\python`，命令其余部分完全一样。
> 双击的入口也从 `bin/xxx.command` 换成 `bin\xxx.bat`。

## 一、作为 Codex / AI Skill 使用

本文件夹根目录的 `SKILL.md` 就是 Codex Skill 定义。安装方式二选一：

**本项目已经装好的两个位置（本机）**

| 工具 | 位置 |
|---|---|
| Codex | `~/.codex/skills/wangxiang-inventory` |
| WorkBuddy | `~/.workbuddy/skills/wangxiang-inventory` |

两个都是**指向同一个项目文件夹的软链接**，所以改一次、两边同时生效。

Windows 上对应的位置是：

```
%USERPROFILE%\.codex\skills\wangxiang-inventory
%USERPROFILE%\.workbuddy\skills\wangxiang-inventory
```

Windows 建软链接需要管理员权限，用目录联接更省事（PowerShell）：

```powershell
New-Item -ItemType Junction -Path "$env:USERPROFILE\.workbuddy\skills\wangxiang-inventory" -Target "C:\wangxiang"
```

---

**方式 A：软链接进 skills 目录（推荐，本机已经这样装好了）**

```bash
ln -sfn /你的路径/skill-WangxiangInventory ~/.codex/skills/wangxiang-inventory
```

用**软链接**而不是复制的好处：以后改了代码/配置，所有会话立刻生效，
不会出现「两份代码版本不一致」。

验证装好了：

```bash
ls ~/.codex/skills/wangxiang-inventory/SKILL.md      # 能读到就 OK
```

之后在**任何新会话**里直接说：

> 用 wangxiang-inventory 帮我把 demo-inventory 里的库存同步到网店

Codex 会自动读 `SKILL.md`（里面有完整命令流程，以及「不允许绕过差异比对、
必须用户确认后才 sync --yes」的硬规则）。

**方式 A2：想复制一份独立的（不共享代码）**

```bash
cp -R /path/to/skill-WangxiangInventory ~/.codex/skills/wangxiang-inventory
cd ~/.codex/skills/wangxiang-inventory && bash bin/setup.sh
```

**方式 B：把整个文件夹丢给 Codex**

在新会话里说：

> 这个文件夹是一个库存同步工具，请先读 SKILL.md 和 README.md，
> 然后帮我跑一遍 extract + diff，把差异报表给我看。

## 二、复制给别人（人类同事）

### 必须一起带走的

```
wangxiang/                代码
bin/                      双击脚本
config/config.example.yaml 配置模板（注意是 example！）
docs/                     文档
requirements.txt
SKILL.md  README.md
```

### **不要**带走的（涉及密钥）

```
config/config.yaml        ← 里面是你的 API 密钥，等于网店后门钥匙
output/                   ← 你的运行结果，可能含经营数据
.venv/                    ← 体积大、且换机器要重建
```

### 打包命令

```bash
cd /path/to
zip -r wangxiang-inventory.zip skill-WangxiangInventory \
  -x "skill-WangxiangInventory/.venv/*" \
  -x "skill-WangxiangInventory/output/*" \
  -x "skill-WangxiangInventory/config/config.yaml" \
  -x "skill-WangxiangInventory/.cache/*"
```

### 对方拿到之后

1. 解压；
2. 终端里 `cd` 进去，执行 `bash bin/setup.sh`（会自动创建 `.venv` 和
   `config/config.yaml`）；
3. 打开 `config/config.yaml`，填**他自己的**店铺网址和**他自己生成的**密钥
   （见 [04-WooCommerce密钥获取](04-WooCommerce密钥获取.md)）；
4. 把 `sources:` 里的 `file:` 指向他自己的库存文件；
5. `.venv/bin/python -m wangxiang check` 通过后就可以用了。

> ⚠️ 千万不要把自己的 `config/config.yaml` 发给别人。让每个人生成自己的密钥，
> 这样以后某人离职，只需要在后台删掉他那把密钥，不影响其他人。

## 三、迁移到别的电脑

1. 把文件夹（不含 `.venv`、`config/config.yaml`、`output/`）拷过去；
2. `bash bin/setup.sh`；
3. 填 `config/config.yaml`；
4. `check` → `extract` → `diff` → `sync`。

---

## 四、换一个店铺用

1. 改 `config/config.yaml` 的 `store` 部分（网址 + 新密钥）；
2. 改 `sources` 部分（新的库存文件）；
3. 删掉 `output/.cache/woo_catalog.json`（否则会用旧店铺的缓存）；
4. 清空或重建 `config/product_map.csv`：

   ```bash
   .venv/bin/python -m wangxiang map --overwrite --write
   ```

5. 重新走 `extract` → `diff`。

---

## 五、交接时应该说清楚的三件事

| 事项 | 说明 |
|---|---|
| 密钥放在哪 | `config/config.yaml`，对方要自己生成一把新的 |
| 哪些来源要处理 | 也就是 `sources:` 的清单，以及每份文件多久更新一次 |
| 谁有权确认同步 | 建议约定：**先看差异报表，再由负责人说「确认」**，才跑 `sync --yes` |

## 六、给下一个维护者（技术向）

- 代码在 `wangxiang/`，纯 Python，没有框架：
  - `util.py` 文本/SKU/尺码规范化
  - `extract_excel.py` / `extract_pdf.py` 解析器
  - `unify.py` 汇总输出统一格式
  - `woo.py` WooCommerce REST 客户端（含本地缓存）
  - `matching.py` 商品匹配 + 映射表读写
  - `diff.py` 比对逻辑
  - `report.py` 彩色报表
  - `sync.py` 提交更新 + 日志
  - `cli.py` 命令行
- 加新解析器：实现 `extract_xxx(path, source_id, options) -> (rows, stats)`，
  在 `unify.extract_one_source()` 里加一个分支即可。
- 报表颜色定义在 `report.py` 顶部的 `FILL_*` 常量。
- 有离线回归自检：`python3 -m wangxiang selftest`。
  基线写在 `tests/baseline.json`（当前：SP5 84 行 / ALO 73 行 / PALLET 850 行，
  共 1007 行；货盘 850 个格子中 552 有勾 / 298 无勾 / 0 临界）。
  它同时会断言 SKU 规范化、尺码别名、`size_map` 解析、重名编号这些易错逻辑。
- `pyproject.toml` 提供了 `wangxiang` 命令行入口，`bash bin/setup.sh` 会自动
  `pip install -e .`。改完代码不用重装。
- 目录结构补充：`tests/baseline.json`（回归基线）、`pyproject.toml`（打包/入口）。
